# ADR: Tika OCR for search, Xberg markdown for LLMs

Date: 2026-10-08  
Status: proposed

## Context

OCR ran only on Apache Tika. Its text is complete and suits full-text search, but tables
are lost, so LLMs reading documents via MCP cannot answer questions about them.
[Xberg](https://github.com/xberg-io/xberg) returns markdown that keeps tables, also in scans
when layout detection, the TATR table model, and PaddleOCR are enabled.

## Decision

Tika and Xberg run independently when configured, each with its own scheduler loop and
status fields on the file:

- Tika fills `ocr_content` with whitespace-joined text as before. Full-text search uses it.
- Xberg fills `ocr_markdown` with layout-aware markdown. MCP `read_file_text` prefers it and
  falls back to the Tika text (`File.LLMText`).
- Without Tika, Xberg also fills `ocr_content` with its text joined the same way, unless the
  file already has OCR content. Such content is marked, and Tika replaces it once configured.

Xberg requests are pinned to markdown, layout for markdown, the TATR table model, and
PaddleOCR with the `latin` model (`xberg.extractConfig`). The Compose files use
`1.3.6-core` with a persistent volume for Xberg's model cache.

## Rationale

Separate fields keep the more complete Tika text for search while giving LLMs the
structure they need. Separate status fields let one engine fail or lag without blocking or
repeating the other. PaddleOCR is required for tables in scans and avoids Tesseract's
dictionary filter in Xberg, which drops lines with names or reference numbers. The models
are downloaded once on first use; a persistent cache avoids downloading them on every start.

## Consequences

- Benefit: search keeps Tika's coverage; MCP clients receive tables as markdown.
- Benefit: the migrations only add nullable columns and partial indexes; `files` is not
  rebuilt.
- Drawback: every document is extracted twice when both engines are configured.
- Drawback: Xberg needs internet access on first use and about 230 MB of model storage.
- Drawback: configuring Tika after running Xberg only processes all files that have
  Xberg-derived search content once more.
- Drawback: Xberg rejects unknown options, so an upgrade that renames one breaks Xberg OCR.
  Upgrades must update the image pin deliberately and recheck the options.
