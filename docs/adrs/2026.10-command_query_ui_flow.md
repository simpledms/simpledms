# ADR: Commit commands before event-driven UI queries

Date: 2026-10-02  
Status: accepted

## Context

The browser UI mixes event-driven partial refreshes, commands rendering lists,
business-content OOB updates, and the `X-Query-Endpoint` same-request dispatcher.
Only selected commands buffer responses until commit. Some page queries also
consume pending uploads. Handler names and POST alone do not distinguish these cases.

## Decision

Adopt the [Command / Query UI Flow](../../AGENTS.md#command--query-ui-flow)
contract as the authoritative policy. Retain the existing monolith, transactions,
widgets, and HTMX partials. Remove the command-then-query dispatcher after migrating
its consumers; use the existing response buffer for write actions by default.

Retain explicit authentication, context/language navigation, opening newly created
resources, native responses, and one-time secrets as exceptions. Upload/WebAuthn
adapters notify islands only after their own persistence succeeds. Read-only
filter/chooser interactions remain queries even where historical names say `Cmd`.

## Rationale

Each island can refresh from its own state and authorization context. A failed
write cannot expose a successful result. Ordinary command adapters no longer own
the screen that happened to initiate them.

## Consequences

- Benefits: reusable commands, independently authorized queries, smaller command
  responses, and consistent transaction visibility.
- Tradeoffs: additional query requests and a visible asynchronous refresh boundary;
  complete event/listener chains, payload decoding, and view-state preservation
  must be maintained and tested together.
- Existing main/tenant transactions remain separate commits; this decision does
  not add cross-database atomicity or durable browser notifications.
