# ADR: Native, version-pinned MCP byte ranges

Date: 2026-09-30
Status: accepted

## Context

Clients need original document bytes, including files larger than one bounded tool response.
Existing browser download URLs require Sessions, and storage objects are encrypted/compressed.

## Decision

Expose `download_file` through the existing bearer-authenticated MCP transport. Return at most
1 MiB plaintext as base64, with size, selected version, byte offsets, and continuation metadata.
Require a version number after offset zero and use the existing canonical storage reader.

## Rationale

This reuses current scope authorization and storage behavior without new transfer credentials,
presigned storage access, or an additional HTTP endpoint. Explicit version selection prevents
silent mixing of content across a concurrent version change.

## Consequences

- Read-only credentials can retrieve original bytes with public references and bounded responses.
- Base64 adds overhead, and encrypted/compressed plaintext ranges require reopening/discarding
  prefixes. Later chunks cost additional I/O; this is not an efficient large-file streaming API.
- Each chunk is freshly authorized. Clients must assemble bytes and carry the returned version.
