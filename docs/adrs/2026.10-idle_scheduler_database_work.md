# Reduce idle scheduler database work

- Date: 2026-10-20
- Status: accepted

## Context

A 120-second production CPU profile recorded 38.45 CPU-seconds. Scheduler tenant
lookups accounted for 14.90 seconds, including 11.49 seconds decrypting and parsing
tenant identities. SQLite statement preparation accounted for 6.92 seconds.
These measurements overlap and must not be added together.

## Decision

Load tenant records and keys on demand after finding work in file copying, OCR,
preview processing, and content-hash backfill. Reuse a loaded tenant within one
preview pass, without caching decrypted keys across passes.

Enable the existing SQLite driver's prepared-statement cache with
`_stmt_cache_size=32` in the shared connection parameters, using
`github.com/mattn/go-sqlite3 v1.14.52` in both the application and SaaS modules.

## Rationale

Avoiding empty-queue tenant lookups removes unnecessary cryptography and
allocations. Reusing prepared statements reduces repeated SQL compilation without
adding a cache of query results or changing polling frequency.

Review reproduced stale result-column metadata after schema changes with driver
version v1.14.50. Version v1.14.52 includes the upstream fix, allowing statement
caching without an application-level connection-recycling workaround.

## Consequences

- Idle passes avoid tenant-key work; existing processing and retry ordering stay
  intact.
- Prepared statements retain memory per connection. A small bounded cache limits
  this cost, but the total still scales with the number of open connections and
  tenants. Diverse query workloads may churn the cache with little benefit.
- Regression coverage in `db/sqlx/sqlite_query_params_test.go` checks committed
  writes, rollback, and result metadata after table and view changes on existing
  read-only and read-write connections.
- Production gains must be measured with another comparable idle profile after
  deployment; the initial profile is a baseline, not a guaranteed saving.

## Verification

With `CGO_ENABLED=1` and tags
`sqlite_fts5 sqlite_json sqlite_foreign_keys sqlite_icu`:

- In `simpledms/`, `go test -count=1 ./db/sqlx -run
  '^TestSQLiteQueryParamsRefreshCached(Table|View)Metadata$'` failed on v1.14.50
  with stale columns for both connection modes.
- After upgrading, `go test -count=1 ./db/sqlx ./scheduler
  ./model/tenant/filesystem ./model/main/tenant` passed, including those regressions.
- The SaaS root compile check, `go test -run '^$' ./...`, was blocked by existing
  context-type mismatches in `model/modelmain/manage_tenants_service_test.go`
  at lines 35 and 131 (`ctxx.Context` passed instead of `*ctxx.VisitorContext`).
- `go list -m github.com/mattn/go-sqlite3` selected v1.14.52 in both modules.
