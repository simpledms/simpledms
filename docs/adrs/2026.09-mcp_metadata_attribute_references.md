# ADR: Address MCP attributes through their definition references

Date: 2026-09-29
Status: accepted

## Context

MCP metadata management needs to edit and remove document-type attributes. Attributes have no
public IDs, but the schema already makes each document-type/Tag and document-type/field pair
unique within a Space. The UI cannot change the referenced definition when editing an attribute.

## Decision

Address an attribute with its document-type public ID plus exactly one Tag or field public ID.
Resolve all references within the credential's Space and call the same attribute model methods
as the UI. Keep Tag and field editing contracts distinct.

## Rationale

The existing relationship identifies the configuration being managed. Reusing it avoids an
attribute-ID migration/backfill and keeps internal IDs out of the public protocol.

## Consequences

- Clients can discover selectors from `get_document_type`; renaming definitions preserves them.
- No schema migration or additional readiness ledger is required.
- Selectors are composite, and deletion/recreation of the same relationship reuses the selector.
  If the UI later permits reference reassignment or duplicate pairs, this contract needs revision.
