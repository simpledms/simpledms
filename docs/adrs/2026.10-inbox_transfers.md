# ADR: Transfers between Inboxes

Date: 2026-10-02  
Status: accepted

## Context

Users need to hand documents to another Space, including Spaces they cannot open.
Classification belongs to the source Space; file versions and note history must travel together.

## Decision

Allow transfers to writable Spaces. Add a disabled-by-default receiving setting, managed by tenant
owners, to also accept transfers from tenant members without destination access. Publish destination
names and public IDs through a narrow model query shared by selection and submission. Sending
confers no destination membership. Keep ordinary Space access policies unchanged.

Transfer the existing file and its notes in one tenant transaction. Make Space ownership mutable
only for these two entities. Store an optional message as a normally attributed document note.
Clear classification after warning in the dialog, as agreed with the user. Remove old WebDAV
upload aliases. Return success only after commit and leave the sender in the source Inbox.

## Rationale

Reusing file identity, storage, notes, and transaction handling avoids copying bytes or creating a
second messaging subsystem. A narrowly scoped Ent migration option represents the new default as
a literal so SQLite adds the column without rebuilding Spaces.

## Consequences

Enabled Space names become discoverable by tenant members. Senders can lose access after a move.
Classification must be assigned again in the destination; it is not mapped across Spaces.
Versions, note history, and storage references retain their identities. Messages follow ordinary
note permissions rather than forming an immutable transfer audit log. Future code changing a
file's Space must use the transfer operation to keep related records consistent.
